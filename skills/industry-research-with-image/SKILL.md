# 图文行业研究报告 Skill

## 核心目标

创建带有 AI 生成配图的行业研究报告，通过系统化工作流完成从规划到成稿的全过程。
最终交付物必须是：

1. 一份结构完整、约 1000 字的 Markdown 报告；
2. 至少一张与正文内容相关的 AI 配图；
3. 图片使用相对路径 `./pic/<filename>.png` 正确引用。

## 强制工作流（顺序不可颠倒）

| 步骤 | 名称 | 关键任务 | 产出 |
| --- | --- | --- | --- |
| 1 | 规划与框架创建 | 使用 `write_todos` 制定步骤；定义报告结构；规划图片位置、描述和文件名；保存框架 | `/workspace/report_framework.md` |
| 2 | 信息收集 | 理解用户需求；使用 `analyze-company` 等技能；谨慎使用 `web_search`；为每个章节收集数据 | 各章节素材 |
| 3 | 先生成图片 | 使用 `image-generator-agent`；按框架生成所有规划图片；输出到 `/workspace/pic/`；使用描述性文件名 | `/workspace/pic/*.png` |
| 4 | 撰写报告内容 | 使用 `writer-agent`；读取框架了解图片位置；围绕图片撰写各章节；覆盖介绍/概念/优势/应用/展望 | `/workspace/report_draft.md` |
| 5 | 插入图片与定稿 | 验证所有图片引用；格式为 `![描述](./pic/文件名.png)`；路径不含 `workspaces`；缺失图片补生成 | `/workspace/final_report.md` |

```text
规划框架 → 收集信息 → 生成图片 → 撰写内容 → 定稿
    ↑          ↑          ↑          ↑
定义结构   收集数据   创建图片   围绕图片写作
 + 图片位置
```

**关键原则**：必须先有图片，再写正文。这样写作时才能围绕图片组织内容，而不是写完后
硬插图。

## Step 1：规划与框架创建

1. 解析用户主题、字数、受众和输出路径。
2. 使用 `write_todos` 建立 5 步计划，并明确每步产出。
3. 在 `/workspace/report_framework.md` 中写出：
   - 标题与一句话摘要；
   - 章节结构：引言 → 行业概述 → 核心技术与应用 → 趋势 → 挑战 → 结论；
   - 每张图片的位置、视觉描述、文件名与尺寸；
   - 每个章节需要收集的数据点。
4. 图片规划至少包含一张“主视觉/行业概览图”。

## Step 2：信息收集

- 优先复用用户提供的资料与已有技能（如 `analyze-company`）。
- `web_search` 成本较高且需要人工审核，**只在关键数据缺失时使用**，并控制调用次数。
- 为每个章节记录“事实 + 来源 + 时间”，禁止编造统计数据。
- 若搜索失败，先尝试调整关键词或改用其他来源，不要直接放弃。

## Step 3：先生成图片

调用 `image-generator-agent`，一次任务生成一张图。给子代理的任务必须包含：

1. 图片主题与视觉概念；
2. 风格：现代、极简、专业、学术；
3. 关键元素（图表、神经网络、金融界面、产业链等）；
4. 配色方案（建议深蓝 + 金色）；
5. 输出文件名与目录：`/workspace/pic/<topic>_<type>.png`；
6. 尺寸：默认 `1664*928`（16:9）。

图片命名格式：`{主题}_{类型}.png`，例如 `ai_finance_2026_overview.png`。
生成后使用 `ls` 或 `read_file` 验证文件存在。

## Step 4：撰写报告内容

调用 `writer-agent` 撰写正文。任务描述必须包含：

- 标题、目标字数（约 1000 字）、语言（中文）、语气（专业、客观）；
- 已收集的素材与数据点；
- 图片引用位置与准确路径：`![AI+金融行业概览](./pic/ai_finance_2026_overview.png)`；
- 章节结构：行业概述、核心技术与应用场景、行业发展趋势、挑战与未来展望。

写作要求：

- 每个章节围绕对应图片展开，避免图片与正文脱节；
- 不使用空泛口号，尽量给出具体场景、数据和判断；
- 结论给出总结与后续观察指标。

## Step 5：插入图片与定稿

1. 读取 `/workspace/report_draft.md`。
2. 检查每个图片引用：
   - 格式必须是 `![描述](./pic/文件名.png)`；
   - 路径中不能出现 `workspaces`；
   - 文件必须真实存在于 `/workspace/pic/`。
3. 缺失的图片重新调用 `image-generator-agent` 生成。
4. 写入最终文件 `/workspace/final_report.md`（或用户指定路径）。
5. 向用户报告：报告路径、图片路径、字数、章节结构。

## 图片生成规范

- 命名：`{主题}_{类型}.png`，小写字母 + 下划线或连字符；
- 提示词要素：视觉概念、风格、关键元素、配色、构图、尺寸；
- 默认尺寸：`1664*928`；也可使用 `1280*720`、`1024*1024`；
- 输出目录：`/workspace/pic/`；
- 禁止使用宿主绝对路径。

## 可用工具

- `write_todos`
- `task`（`writer-agent`、`image-generator-agent`）
- `read_file` / `write_file` / `edit_file`
- `ls` / `glob` / `grep`
- `web_search`

## 质量检查清单（8 项）

- [ ] 结构清晰且有标题层级
- [ ] 引言能吸引读者
- [ ] 每个章节内容充实
- [ ] 图片与内容相关
- [ ] 图片文件名具描述性
- [ ] 图片置于逻辑断点处
- [ ] Alt 文本描述图片内容
- [ ] 结论提供总结和后续步骤

## 重要约束

- 严格遵守五步顺序，不得先写正文再补图。
- 不得编造图片已生成；必须验证文件存在。
- 不得把图片保存到 `/workspace` 根目录，必须放在 `/workspace/pic/`。
- 报告中的图片引用使用 `./pic/...` 相对路径。
