# 行业研究写作参考资料

本文件是 `industry-research-with-image` Skill 的参考材料，按需读取。

## 一、博客/报告结构模板

### 1. 技术产品博客

| 部分 | 内容 |
| --- | --- |
| 标题 | 明确产品名与核心价值 |
| 简介 | 一句话说明是什么、解决什么问题 |
| 核心功能 | 3–5 个功能点，配截图或示意图 |
| 优势 | 与替代方案的对比 |
| 应用场景 | 2–3 个真实场景 |
| 未来展望 | 产品路线与行业趋势 |
| 结论 | 总结与行动建议 |

结构：标题 → 简介 → 核心功能 → 优势 → 应用场景 → 未来展望 → 结论

### 2. 教程/操作指南

| 部分 | 内容 |
| --- | --- |
| 标题 | 动词开头，说明可完成的任务 |
| 简介 + 前置条件 | 环境、依赖、权限 |
| 分步指引 | 每步一个动作，配命令/截图 |
| 最佳实践 | 常见坑与优化建议 |
| 故障排查 | 错误现象 → 原因 → 解决 |
| 结论 | 回顾与下一步 |

结构：标题 → 简介 + 前置条件 → 分步指引 → 最佳实践 → 故障排查 → 结论

## 二、图片放置指南

| 博客章节 | 图片类型 | 推荐尺寸 |
| --- | --- | --- |
| 引言/开头 | 主视觉横幅 | 1200×630 |
| 概念解释 | 示意图 | 800×600 |
| 功能展示 | 截图 | 1024×768 |
| 流程说明 | 流程图 | 1200×800 |
| 总结部分 | 图标集 | 600×400 |

本项目默认使用 DashScope 支持的尺寸：`1664*928`、`1280*720`、`1024*1024`、
`720*1280`。

## 三、图片命名规范

- 格式：小写字母 + 下划线或连字符；
- 示例：`concept_overview.png`、`feature_workflow.png`、`architecture_diagram.png`；
- 文件名必须能看出主题与类型，禁止 `image1.png`、`tmp.png`。

## 四、图片提示词模板

| 类型 | 提示词模板 |
| --- | --- |
| 概念插图 | “专业插图展示[概念]，包含[关键元素]，现代极简风格，蓝白配色，简洁设计” |
| 技术图示 | “清晰技术图示显示[系统/流程]，标注组件，专业演示风格，浅色背景，矢量风格” |
| 主视觉图 | “关于[主题]的精美主视觉，动态构图，专业光影，高质量，适合博客头部” |

补充要求：

- 横版 16:9，留白充足；
- 避免真实人物肖像与受版权保护的角色；
- 图中文字尽量少，避免模型生成错别字；
- 金融主题建议深蓝 + 金色，学术主题建议白底 + 深灰 + 单一强调色。

## 五、子代理任务模板

### Writer Agent（写作代理）

- 结构：简介 → 核心概念/功能 → 优势 → 应用场景 → 未来展望 → 结论
- 必须指定：语言、语气风格、目标字数、图片引用路径
- 只负责写作，不负责搜索、研究或生成图片

### Image Generator Agent（图片生成代理）

- 必须提供：视觉描述、风格（现代/极简/专业/学术）、关键元素、配色、尺寸、输出文件名
- 只调用一次 `generate_image`；失败时如实报告，不要假装成功

## 六、质量检查清单（8 项）

- [ ] 结构清晰且有标题层级
- [ ] 引言能吸引读者
- [ ] 每个章节内容充实
- [ ] 图片与内容相关
- [ ] 图片文件名具描述性
- [ ] 图片置于逻辑断点处
- [ ] Alt 文本描述图片内容
- [ ] 结论提供总结和后续步骤

## 七、事实与引用规范

- 每个关键数据点注明来源与时间；
- 区分“事实”“预测”“观点”；
- 不把模拟数据写成真实市场数据；
- 搜索摘要不能直接当作唯一证据，重要结论至少交叉验证一次。
